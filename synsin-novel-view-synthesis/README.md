# Novel View Synthesis with SynSin

This repository contains an implementation and evaluation of **Novel View Synthesis using the pretrained SynSin model**.

The project applies SynSin to custom input images and tests how well the pretrained model generalizes to images that are different from the scenes used during training.

## Project Overview

Novel view synthesis is the task of generating a new view of a scene or object from an existing input image and a desired camera transformation.

In this project, the pretrained **SynSin** model was used to synthesize new views from a single input image. The model was not trained from scratch. Instead, a pretrained RealEstate10K checkpoint was loaded and used only for inference.

The main purpose of the project was to evaluate SynSin on out-of-domain examples, including:

- a single chess piece;
- a top-view scene with a book and a clock;
- a close-up portrait of a human face.

These images differ from the scene-centric data used in the original SynSin training setup, making them useful for testing the model's generalization ability.

## Objective

The objectives of this project are:

- to apply the pretrained SynSin model to novel view synthesis;
- to generate new views from single input images;
- to test the model on custom out-of-domain images;
- to analyze visual artifacts and reconstruction quality;
- to compare the results with typical in-domain SynSin behavior.

## Background

SynSin is an end-to-end method for novel view synthesis from a single image.

The model takes:

```text
Input image I
Relative camera transformation T
```

and generates a new image from a different viewpoint.

The original SynSin pipeline includes:

1. A spatial feature network
2. A depth regressor
3. A neural point cloud renderer
4. A refinement network

The model predicts a latent 3D point cloud of features, renders this representation from a new viewpoint, and then refines the rendered output to produce the final synthesized image.

## Model Architecture

The SynSin pipeline can be summarized as follows:

```text
Input Image
    ↓
Feature Extraction
    ↓
Depth Prediction
    ↓
Latent 3D Point Cloud Construction
    ↓
Neural Point Cloud Rendering
    ↓
Image Refinement Network
    ↓
Synthesized Novel View
```

The model learns an implicit 3D-aware representation without requiring ground-truth 3D supervision during training.

## Pretrained Checkpoint

The project used the pretrained RealEstate10K checkpoint:

```text
./modelcheckpoints/realestate/zbufferpts.pth
```

The checkpoint was loaded in test mode and used for inference only.

The original SynSin training loss was not used directly in this project because no training from scratch was performed.

## Image Preprocessing

Before inference, each input image was preprocessed using the following steps:

1. Resize the image to `256 x 256`
2. Convert the image to tensor format
3. Normalize the tensor
4. Pass the image into the pretrained SynSin model

## Viewpoint Transformation

Novel views were generated by manually selecting small camera transformation parameters:

```text
theta, phi, tx, ty, tz
```

In the final implementation, `scipy.spatial.transform.Rotation` was used to construct the rotation matrix.

The transformation was then passed into the model through the inference function.

## Test Images

Three custom images were used.

| Image | Description | Domain Shift |
|---|---|---|
| Bishop | Single chess piece on a simple background | Moderate |
| Book and clock | Top-view object scene | Strong |
| Face portrait | Close-up human face | Very strong |

These images were intentionally selected because they differ from RealEstate10K-style property walkthrough images.

## Final Viewpoint Settings

The final selected transformation settings were:

```text
bishop:  theta = -0.08, phi =  0.05, tz = 0.08
books:   theta = -0.08, phi = -0.05, tz = 0.08
face:    theta = -0.05, phi =  0.03, tz = 0.06
```

Small transformations were used because larger viewpoint changes produced stronger artifacts.

## Results

### 1. Chess Piece

The chess piece produced the strongest result.

Observations:

- the silhouette was preserved reasonably well;
- the object remained recognizable;
- the synthesized output showed a visible perspective change;
- the simple background helped the model produce a stable result.

Artifacts:

- slight blur near image borders;
- mild contour smoothing;
- coarse depth structure.

This result was the best among the three because the image contained a centered object and a simple background.

### 2. Book and Clock

The book-and-clock image produced a moderate result.

Observations:

- the general scene layout was preserved;
- the book, clock, and wooden surface remained recognizable;
- the synthesized view showed a reasonable transformation.

Artifacts:

- geometric warping around the clock;
- less precise rectangular book edges;
- background texture blur.

This result suggests that SynSin can preserve global layout, but struggles with unusual top-view scenes that differ from its training distribution.

### 3. Close-up Face

The close-up face produced the weakest result.

Observations:

- the person remained recognizable;
- the generated image contained strong local distortions;
- fine facial geometry was not preserved accurately.

Artifacts:

- facial warping;
- distortions around glasses;
- unstable face contour;
- blurred hairline and background;
- overly smooth depth prediction.

This was expected because SynSin was trained mainly on scene-centric datasets, not close-up portrait images.

## Comparison with In-Domain SynSin Results

In the original SynSin paper, the model performs best on scene-based inputs such as:

- indoor rooms;
- hallways;
- furniture layouts;
- property walkthrough images;
- outdoor scene views.

Compared with those examples, the custom results in this project contained more visible artifacts because the input images were outside the RealEstate10K training domain.

## Main Findings

The project shows that SynSin can generate plausible novel views for simple out-of-domain images, but its performance decreases as the input becomes less similar to the training data.

Main conclusions:

- SynSin works best on scene-like images similar to RealEstate10K.
- Simple objects with clean backgrounds can still produce reasonable results.
- Top-view scenes cause geometric and texture distortions.
- Close-up faces are difficult because they require fine-grained geometry.
- Small viewpoint changes are more stable than large transformations.
- Domain shift has a strong effect on novel view synthesis quality.

## Limitations

The main limitations observed in this project were:

- visible blur in synthesized outputs;
- incorrect or coarse depth prediction;
- object boundary distortions;
- unstable results on close-up faces;
- artifacts under strong viewpoint changes;
- reduced quality for images outside the RealEstate10K domain.

## Possible Improvements

Future improvements could include:

- fine-tuning SynSin on object-centric or portrait datasets;
- testing more in-domain RealEstate10K-style images;
- comparing different camera transformation values;
- evaluating outputs quantitatively if ground-truth target views are available;
- testing other novel view synthesis methods;
- using higher-resolution inputs;
- improving depth estimation for non-scene images.

## Conclusion

This project successfully applied the pretrained SynSin model to novel view synthesis on three custom images.

The results showed that the model can generate plausible new views for simple inputs, but it struggles with strong domain shifts such as close-up faces and unusual top-view scenes.

The best result was achieved on the single chess piece image, while the weakest result was observed on the close-up face image.

Overall, the project demonstrates both the potential and the limitations of pretrained novel view synthesis models when applied outside their original training domain.
